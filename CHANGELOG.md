## [0.9.0] — Unreleased

### Added
- **Observation-seat state CHECKPOINTS (backend)** — replay no longer has to re-execute an entire build history: the field case ("x-wing v3 — material era", 588 events, a ~20-minute `simplify` + a 109-call `refine_region` campaign) froze the observer's tab at 90/318 commands, and re-execution is architecturally unfixable — so the performer now snapshots FULL SCENE STATE and observers restore + replay only the tail. Backend protocol (frontend implements against `/tmp/observe_checkpoint_protocol.md`):
  - **`exec_ms` telemetry**: the publish hook patches the ONE `mv.execute` facade every MCP dispatch path funnels through and attaches measured engine time to each published command event (the frontend's progress/ETA signal; also what the capture triggers integrate).
  - **Capture triggers with an overhead governor**: a >2 s command (the monster rule — no replay segment hides a monster in its middle), 15 s cumulative engine time, or 40 mutating commands ARM a capture; it FIRES when a budget accrued at 8% of engine time covers the MEASURED capture cost (a fixed 15 s interval would blow the overhead cap on heavy sessions: 63 min of engine time ÷ 15 s ≈ 250 captures), seeded so short sessions still get their first checkpoint; session end always captures when state changed; never on read-only commands. Captures run in-page behind the same execute gate — a snapshot can never be torn by a concurrent command. Measured: +7.0% wall on a heavy owl segment (10.2 s engine, 2 captures); capture 223 ms on a 217k-tri/13.6 MB-texture scene, 46 ms on 154k tris.
  - **Per-object GLB blobs + identity manifest — the identity problem solved**: a whole-scene GLB flattens N objects into one and re-import assigns fresh ids, so every post-checkpoint command addressing an object id would miss. Each object exports ALONE with its wrapper neutralized (geometry object-local; placement lives in the manifest), and the manifest carries ids, names, logical TRS, pivots, hierarchy, visibility/opacity, modelScale, `geometryRev`, morph weights, `nextObjectId`/`activeObjectId`, display+lighting, the timeline, and the state fingerprint. Restore = `add_model` per blob + public commands + three documented direct assignments (`entry.id`, `entry.geometryRev`, `viewer._nextObjectId`); proven end-to-end in `tests/e2e/test_observe_checkpoints.py`: fingerprint parity after restore, and a post-checkpoint tail (including a `remove_object` id GAP followed by new adds) replays to EXACT convergence with the performer (fingerprint, transforms, timeline, roster).
  - **Hub storage, bounded three ways**: ≤8 checkpoints/session (evenly-spaced thinning; the newest and the final snapshot always survive), ≤64 MB/blob (a 217k-tri scene measures 13.6 MB; the x-wing's 1.48M-tri peak extrapolates to ~45 MB — the brief's 25 MB cap would have refused exactly the sessions that need checkpoints), ≤256 MB/session and ≤512 MB globally (oldest-activity sessions shed first — 8 retained recordings must not pin ~1 GB of app RSS). Uploads ride the performer's ORDERED event pipe, so the hub anchors each checkpoint to the seq of the last appended event with no mapping table; failures degrade to honest `checkpoint_skipped` lifecycle notes.
  - **API**: `/api/observe/sessions` rows gain `checkpoints:[{seq, bytes, ts, exec_ms_since_start, objects, final, reason, capture_ms}]` + `first_seq`; `GET /api/observe/checkpoint?session&seq` returns the manifest (JSON), `…&object=<id>` the GLB blob (`model/gltf-binary`) — split so browsers need no unzip dependency and blob fetches parallelize; the SSE stream accepts `from=<seq>` (default 0 = exact old behavior) and emits `{type:"checkpoint"}` markers right after their anchor entries (markers consume no entry seq; pre-checkpoint clients ignore unknown types — regression-proven with the existing observe suite). Sessions whose ring dropped early events are now joinable FROM a checkpoint instead of permanently unwatchable.
- **The observation SEAT consumes checkpoints (frontend integration)** — the two halves joined: LIVE joins pick the newest usable checkpoint from the session row, stream `from=seq+1`, and RESTORE (per-object blobs → identity triple → hierarchy → transforms → timeline → display) instead of re-executing history, with the restored replica verified against the manifest fingerprint and an automatic fall-back to replay-from-zero when anything mismatches (honesty: the banner says "restored from checkpoint — earlier steps were not re-executed"). RECORDING seeks route through `exec_ms` cost arithmetic: a seek (including the initial jump-to-latest and every BACKWARD scrub) restores the nearest checkpoint ≤ target whenever snapshot+tail is measurably cheaper than re-execution — the recorded ~20-minute `simplify` can never re-run in an observer's tab again. Sessions with checkpoints show ⚡ in the panel; a session that ends between the list snapshot and the hello downgrades gracefully to the full-log recording path. `tests/e2e/test_observe_seat_checkpoints.py` proves the whole seat chain: live join restores (measured ~3-5 s against a session whose history contains a >10 s monster), tail id continuity through the restored `nextObjectId` counter, transform/triangle fidelity, zero replay errors, end-jump + backward scrub both taking the checkpoint route.
- **Five-agent performance gauntlet** (field mandate: "you should never have to add 100k triangles in a single sequence" + continued seat slowness) — five adversarial investigators profiled refine over-generation, sculpt/paint hotspots, replay residuals and probe/transport costs; every fix shipped with measured before/after:
  - **`refine_region` no longer floods**: the shark-fin scenario (capsule stock + regularize + r=0.3 refine) added **198k triangles — 93% outside the requested ball — then deadlocked** on an impossible budget refusal; it now adds **416**. Causes fixed: the quality-gate cascade is CLAMPED to 1.5× the brush radius (2-marked triangles beyond it emit a conformal 1→3 split — still no T-junctions), the 12° gate became RELATIVE (green splits of slivers that aren't meaningfully worse than their parents stay green — red children of slivers re-triggered every pass), capsule primitives build square body quads instead of THREE's single-segment ~50:1 slivers (the flood fuel), and budget refusals now DIAGNOSE flooding ("N marked from only M over-target — regularize first") instead of daring the agent to raise the budget.
  - **Live sculpt commands were 75-80% advisory surveys** (three full-mesh edge scans per command): surveys now use a per-command world-position cache + stamp-AABB culling and the out-of-band fraction derives from the post-survey's own lengths — multiset-identical results, `remesh:"auto"` decisions unchanged, replays bit-identical (verified by position+normal hashes).
  - **First paint on a fresh layer froze for ~20 s under SwiftShader**: paint-layer canvases were GPU-backed, and the first readback (undo stash) paid a 23.5-second sync; every canvas that becomes a paint layer now passes `willReadFrequently` (23.5 s → 2 ms). Paint's per-stamp candidate scan also stopped re-transforming every triangle per stamp (per-command Float64 centroid cache, bit-identical selection): a 30-point stroke on a 124k mesh went **20.1 s → 0.22 s**.
  - **`clone_paint` could hang for minutes with no way to tell**: it lacked mirror_paint's correspondence budget (measured 119 s at r=0.4 on 240k) — now refuses over 600M tests with the teaching message, and its per-texel sampling gained an exactness-preserving centroid prefilter.
  - **Raycast/pick are now BVH-accelerated** (~26 ms → ~0.9 ms per probe on dense meshes): three-mesh-bvh was already bundled but never wired into the probe path; trees build lazily per geometry (`indirect: true` — the default build REORDERS the index, and triangle iteration order breaks ties in several deterministic algorithms), invalidate on geometryRev, and skip morphed/skinned surfaces (the tree indexes base positions; three's default raycast handles displaced surfaces — caught by the morph suite).
  - **Replay-divergence P0**: object ids survived `unload` (`_nextObjectId` never reset), so replica rebuilds after an unload — backward seeks, re-joins — addressed objects by stale ids and **438/510 replayed commands silently failed**; ids now restart at 1 on every clear.
  - Also deferred during bulk replay: per-command stats recomputation (vertex-dedup Map churn; settled exactly at `endBulkReplay` and before every fingerprint check, so divergence banners never compare stale numbers). Transport measured innocent: MCP tax ~20-52 ms/call (batch amortizes), SSE ~1% of replay wall-time; screenshot cost is SYNC-bound, not pixel-bound (each new capture size pays a one-time 2.4-28 s warm; `ssao:false` is NOT faster — old claim refuted, guidance corrected). The skill gained the refine budget formula (≈ 2.5·πr²/0.43t²), the graded nested-rings recipe (equal sculpt quality at 13% of the triangles), the flood-refusal reading, probe batching, and the one-size screenshot rule.
- **Observation-seat catch-up and recording replay were "extremely slow" (field report)** — three compounding causes, all fixed: (1) `finalizeSculpt` recomputed vertex normals over the WHOLE geometry after every replayed command (the dominant cost on dense meshes — a 60k-vert sphere paid ~200 ms per stamp); during bulk replay normals now DEFER via a dirty flag and every reader (`averageWorldNormal`, `weldWorldNormal`, refine/simplify/split attribute copies) goes through `ensureFreshNormals`, so any command that needs normals sees exactly the eagerly-computed values — a mixed 40-command sequence + topology op hashes bit-identical positions AND normals between live and bulk paths, and the sculpt-heavy benchmark runs **8.6× faster** (3211 ms → 372 ms for 120 stamps); (2) the pre/post **edge surveys** (three full-mesh scans per sculpt command that only feed the returned advisory) are skipped during bulk replay when they cannot affect geometry (`remesh:"auto"` keeps them — its trigger decision IS geometry); (3) fast-forward progress was INVISIBLE — replay chains microtasks and never yields a frame, so the banner updated but never painted and the seat read as frozen; catch-up now yields every 10 commands with a live `N/total` banner, and recording seeks yield every 20 while advancing the scrub thumb.
- **Recording seeks inherit the same speedup** (backward scrubs rebuild from zero under bulk replay — the deferral applies), and deferred normals are settled once in `endBulkReplay` BEFORE the first visible frame, so nothing ever renders stale shading.
- **Observation-seat replay: the tab could still freeze (Firefox "page is slowing down") and Cancel was broken** — adversarial re-profiling of the REAL owl v3 recording (176 mutating commands replayed id-aligned in headless Chromium) found the residual causes and fixed them with before/after numbers:
  - **The yield scheduler counted COMMANDS, not time** (every 10 live / 20 seek): ten heavy commands fit between yields and blocked the main thread for seconds — measured worst block 3.6-8.5 s per run on the owl catch-up. Both replay loops now run on an ~80 ms TIME BUDGET (`REPLAY_BUDGET_MS`), then yield one real frame: post-paint resume via rAF→timeout when the tab is visible (progress actually reaches the screen), an unthrottled MessageChannel macrotask when hidden (background tabs clamp timers to ~1 s and never fire rAF — a timer-based yield would have slowed hidden catch-ups ~12×). Worst main-thread block fell to ~1.5 s = the single largest irreducible engine command (refine_region/merge_objects); every other gap sits under the budget. Total catch-up time is engine-bound and unchanged (~13 s for the owl session).
  - **Leaving mid-catch-up threw and could leak commands across sessions**: `leave()` emptied the log while the seek loop kept indexing it (`undefined.kind` TypeError as an unhandled rejection), and a fast leave→re-join let session A's still-queued replay continuations execute inside session B's scene (both check `observing`, which the re-join set true again). A run-generation counter (`_runId`, bumped on every join AND leave) is now captured by every queued continuation and checked after every await — Cancel interrupts a running catch-up at the next yield (measured ~1 s, bounded by the in-flight engine command) and stale continuations are orphaned by construction.
  - **Progress UI**: the fast-forward banner now shows N/M + % updated at EVERY yield, a compositor-driven CSS spinner (it visibly moves even while replay JS holds the main thread between yields), and a working Cancel button — recordings' initial jump-to-end and scrub rebuilds show the same progress (they previously showed nothing but the scrub thumb). Replay-error honesty at the end of catch-up/seeks: progress updates used to overwrite the per-error divergence banner and `caught_up` then hid it entirely; the standing "N replay error(s) — replica may have diverged" warning is re-asserted once the dust settles.
  - **`beginBulkReplay` didn't stop an ALREADY-RUNNING render loop**: `invalidate()` gates new resumes during bulk replay, but the rAF loop is almost always live when a catch-up starts, and every command's invalidate re-armed `_renderRequested` — so frames (and full painted-texture re-uploads, 16 MB per dirty 2048² layer) kept rendering mid-catch-up (measured: 10 bulk-mode composer renders on one owl replay; far worse on a real GPU where uploads dominate). The loop now idle-parks while `_bulkReplay` is set; `endBulkReplay → invalidate()` paints the accumulated state once, which also defers all texture GPU uploads to that single first frame.
  - **Brush-undo stashes during replay** (hypothesis confirmed but measured MINOR here): paint_pattern/bake_ao stash the full canvas per command (16 MB getImageData on 2048²) for an undo no observer can invoke — measured ~0.1-0.2 s of the owl's ~13 s replay (willReadFrequently canvases are CPU-backed, so the copy is a memcpy, not a GPU readback). Suppressed during recording seeks ONLY when an exact log scan (batch sub-commands included) proves no replayed `undo_paint` consumes the stash — live replay keeps stashing because a live performer may still publish undo_paint, and a replica that cannot honor it diverges. The suppression flag dies with `endBulkReplay` (it must never outlive bulk mode, or a human's own paint undo would silently stop working), and the seat clears the single-slot brush undo on join AND leave (a pre-join stash points at layers the replica unload disposed; a post-replay stash describes the performer's work, not the user's).
  - **Measured and REJECTED**: per-command `execute` promise overhead (exec time ≈ replayCore time for every action — no batching needed), the set_camera save/restore envelope (0 occurrences in both real logs; only `project_paint` carries envelopes), and ghost/toast/banner churn during fast-forward (already skipped). The x-wing session remains irreducibly slow (its 109 refine_region + 2 whole-model simplify are single-command engine costs of 191 s and 544 s in headless — one `simplify` blocked 440 s); per-action profiles recorded as evidence for the checkpoint work.
  - Field observation for the checkpoint agent: the as-recorded owl session starts with `remove_object {id:1}` for an object created BEFORE publishing began, so a replica replaying from an empty scene drifts every object id by one — 111/176 commands failed (wrong/missing object) and the "fast" replay was doing almost none of the real work. Replays only reproduce the performer's engine load (and scene!) when the log's id space is aligned from zero — exactly what an initial-state checkpoint provides.

### Added
- **Observation-seat FLUIDITY round: frame-paced shows + live broadcast delay** (field verdict on the watchable-playback round: "not very fluid to observe an AI working — it was better before"). Diagnosis with rAF frame-gap instrumentation on the REAL falcon v3 recording: the pacing engine was COMMAND-paced — each 150-800 ms engine command executed between dwells, freezing rendering exactly when the show should be smoothest (72% of playback wall time sat inside >100 ms frame gaps; consecutive heavies fused into a 9.5 s single gap because dwell only separated commands, not frames) — and LIVE observation replayed publish bursts back-to-back as they arrived (2 ms inter-command flashes, then silence). Fixes, all measured before/after in the report:
  - **Frame-paced show engine** (`_frameShow`, shared by recording playback and the live drain): an rAF ticker executes AT MOST one due entry per frame — at least one real frame separates any two commands, so ghost fades, cursor glides and camera lerps animate continuously; a single heavy command's block remains the irreducible engine cost (checkpoint compression still bypasses monsters). Hidden tabs fall back to a coarse interval (rAF parks there). Playback cadence now follows the RECORDED rhythm: dwell = the performer's own publish gap, clamped to [140 ms, 2 s] ("⏸ agent pause compressed" chip past 4 s), scaled by the 0.5-4× selector.
  - **Live smoothing buffer (broadcast delay)**: after catch-up the seat deliberately runs a few seconds behind — stream entries queue and the frame-paced drain replays them at the publish rhythm (ghosts get their fade time; the follow camera glides through every telemetry sample instead of snapping at 5 Hz). Dwell compresses smoothly as lag climbs from 2.5 s toward 7 s; past that the drain RUSHES (ghost-less fast path, budget-bounded per frame, "⏩ falling behind — catching up…" chip) back under the target. The panel shows the honest "● live · Ns behind" readout (amber while rushing). Ordering across the catch-up boundary is exact: the drain chains onto the same replay queue, gated synchronously at the caught_up message. Ended/desynced flows drain-then-banner (desync clears the buffer — replaying onto a divergent state is worse than stopping).
  - **Per-frame animator cleanups found by the same instrumentation**: the ghost cursor now interpolates continuously (position lerp + orientation slerp between per-point surface frames — the 45 ms setInterval stepped at ~22 Hz), trail stamps share one unit ring/disc geometry (per-stamp RingGeometry allocation was pure GC churn), the narration ticker batches DOM writes to ≤5/s, and action chips throttle to ≥400 ms apart (force-bypassed for heavy/catch-up chips that must never be swallowed).
  - E2e: the replay-UX suite gained frame-paced fluidity checks (frames flow between commands, no back-to-back fusion) and a new live-smoothing test (burst buffered not frantic, drain cadence ≥90 ms, lag bounded <8 s with the readout visible, cursor present, zero replay errors, session deleted).
- **Observation-seat replay UX round: fast scrubbing + a watchable show** (field verdict on the previous round: "not impressed — much too slow, and I can't see what the AI did"). Measured on a purpose-built 129-event bench recording (300k-tri era, one 10 s regularize monster, paints/patterns/sweeps) in headless Chromium/SwiftShader; every number below is the same protocol before/after:
  - **Checkpoint cache** (`frontend/js/observe_replay.js`): manifests + blob object-URLs fetch ONCE per session (warmed in parallel with the log buffering) and every later seek restores from memory — the old path re-fetched and re-parsed the blobs per seek (8 checkpoint fetches across 5 scrubs before; 3 — one per distinct checkpoint — after, and 0 on repeats). ### Added
- **`sculpt_sweep` — one weight field per stroke** (retrospective lever #4, the last sculpting item: stamp chains bead because every stamp is an independent radial field — overlaps scallop). A sweep computes each vertex's distance to the whole CURVE once, so the cross-section (`profile: "crease"` sharp V for panel lines, `"round"` dome, `"flat"` plateau trench) is constant along the path; negative strength cuts, positive raises. Majority-side guard: welds facing away from the stroke's weighted mean normal are skipped, so a wing's top panel line cannot groove the bottom skin sitting within radius (verified: slab bottom bit-identical after a top crease). Symmetric sweeps run the mirrored curve as a SEPARATE polyline (no phantom bridge through the object; crests verified bit-symmetric), and the sculpt meshQuality advisory + `remesh:"auto"` carry over. `tests/e2e/test_sweep_ao.py`.
- **`bake_ao` — cavity grounding into the albedo** (retrospective lever #5's second half: "paint sits ON the surface instead of IN it"). Per-weld Laplacian curvature — concavities darken (dirt/shadow pool in seams, folds, panel lines), convex rims optionally lighten (`highlight` — worn edges). Deterministic and instant (no rays), rasterized through the same UV triangle path as patterns, participates in paint undo, and honest about its method: the result reports `method:"curvature"`, and uniform-curvature surfaces (a perfect sphere) REFUSE with the reason instead of "succeeding" invisibly (`shadedTexels` counts actually-changed texels).
- **`deform_region` — closed-form spine deformers** (retrospective lever: "boxes stay boxy because nothing can bend/taper/twist" — the shark tail took 9 grab pulls and terraced). `kind: "taper"|"bend"|"twist"|"stretch"` along `axis {from, to}`: `from` stays anchored, the effect eases (smoothstep) to full at `to` — taper scales cross-sections to `factor` (a mandible/tail/limb taper in ONE call, verified: flank 0.30 → 0.184 at the tip with the base bit-anchored), bend rotates progressively about a perpendicular `direction`, twist about the spine, stretch elongates. Welded (seams never tear), deterministic, reset-snapshot aware, mesh stays closed (openEdges invariant in the suite); teaching refusals for parallel bend axes and zero-touch spines.
- **`bake_normals` — height channel → tangent-space normal map** (the other half of the shipped height channel). Paint relief with any brush or pattern into `channel:"height"` (0.5 = flat), then Sobel-bake it: micro-relief that shades under light at ZERO triangles, survives simplify, and exports as a standard glTF normalMap (a Worley height pattern turns a smooth sphere into hammered metal in two commands). `strength` scales the gradient; re-runs overwrite; `clear_paint` restores the pre-bake normal map and refunds the budget. Honest limits disclosed: island-border seams (Sobel clamps at canvas edges), and bakes never change the silhouette — real relief needs the noise sculpt tool. `tests/e2e/test_deform_bake.py` covers both.
- **Material-channel painting — surfaces finally respond to light** (retrospective lever #1: "everything shades as matte clay/plastic" because paint was albedo-only over a constant material). `paint`/`paint_stroke`/`fill_paint` accept `channel: "roughness"|"metalness"` (+`value` 0..1), `"emissive"` (+color) and `"height"` (data layer): per-texel light response with the full brush vocabulary (falloff, hardness, symmetry, undo groups, gesture ledger). roughness+metalness share ONE packed canvas in glTF's native G/B layout — created seeded from the material's authored map or scalars (scalars neutralize to 1 so the canvas alone carries the values), exported as a single metallicRoughnessTexture, and the exporter bug that silently DROPPED roughness/metalness maps from every GLB is fixed (round-trip verified pixel-identical). clear_paint restores the pre-paint material response and refunds the texel budget; teaching errors name the missing `value`. `tests/e2e/test_material_channels.py`.
- **`paint_pattern` — deterministic procedural texturing in one call** (retrospective lever #2: the falcon's hull mosaic was 160 hand-batched stamps). Six generators — noise (fBm blend), grunge (ridged fBm + contrast), cells (Worley), speckle, stripes, gradient — evaluated in WORLD space per texel via the triangle rasterizer: continuous across UV seams and islands, scale-consistent over the whole object, and bit-identical per {seed, scale} (integer-hash value noise, no transcendentals, no Math.random — pattern-determinism asserted in the suite). Works on every material channel (`channel:"roughness"` + {value, value2} = procedural wear — the cheap realism move), takes an optional world-sphere `region`, blends with `opacity`, and participates in paint undo.
- **`sculpt {tool:"noise"}` — seeded fBm micro-relief** (retrospective lever: the "empty mid-band" between brush domes and paint texels — feathers, bark, rock, fabric). ## [0.1.0] — 2026-02-11

Initial public release of MeshVault.

### What is this project?

MeshVault is a local tool for 3D artists and game developers to browse, preview, transform, and export 3D models. Runs in your browser, stays on your machine.

### Formats
- **3D**: `.obj` (+MTL/textures), `.fbx` (v7000+ native, older auto-converted), `.gltf`/`.glb`, `.stl`, `.blend` (via Blender CLI), `.max` (detection only)
- **Archives**: `.zip`, `.rar` (multi-tool fallback), `.unitypackage` (native parser)

### File Browsing
- Sidebar tree with list/grid view, sort (name/size/type), search filter
- Right-click context menu: inline rename, duplicate, delete, show in file manager
- Remember last directory across sessions (localStorage)
- Color-coded badges per format

### 3D Viewer
- PBR rendering: 5-light setup, SSAO, ACES tone mapping, soft shadows
- Orbit + FPV drone navigation with smooth mode transitions
- 8-button viewer toolbar: screenshot, grid (adaptive), XYZ axes (labeled), wireframe, normals viz, texture folder picker, material inspector (draggable), light panel
- All scene settings persist across model loads
- Race condition guard for rapid asset switching
- FBX preview stabilization: normalize near-black textured multipliers, clamp extreme metalness without IBL, and sanitize accidental ultra-low opacity materials
- FBX fallback texture binding: when FBX files omit texture links, MeshVault now auto-binds related extracted textures by naming conventions (`_d`, `_n`, `_ao`, etc.)
- Robust texture fallback upgraded: per-material scoring, numeric token matching (`01` ↔ `1`), OpenGL-vs-DirectX normal preference, and native TGA loading support
- FBX resource resolver now maps relative/absolute texture references to `/api/asset/related` using source file path, fixing wrong requests like `/api/asset/*.jpg`
- Missing/broken texture references are now sanitized before shading fallback so dark materials are still made readable
- Fixed FBX regression: internal model URL (`/api/asset/file?...`) is no longer rewritten to `/api/asset/related`, preventing load failures
- FBX fallback now detects likely non-color diffuse assignments (e.g. gloss/spec `_g`) and can rebind to better color maps when available
- Emissive textures are now classified/bound in fallback and preserved during legacy material → PBR upgrade
- Rotation robustness improved for multi-part models: rotate now applies one world-pivot transform to the whole object, preventing per-part origin drift
- Bake-world-transform now safely clones shared geometries before baking to avoid double-transform corruption on reused mesh buffers
- Recenter/ground/auto-orient/reset now re-sync spatial state (axis anchor, ground plane, grid, light target, stats) after transforms without changing camera pose

- Filesystem export now gracefully handles source==destination paths (no SameFile copy error on Save to same file)
- Scale slider upgraded to 0.05×–10× with improved visual styling and filled-progress track

### Model Transforms
- Reload, reset (geometry snapshot restore), center, ground, PCA auto-orient, rotate ±90° per axis
- Mesh simplification: merge vertices → edge collapse (SimplifyModifier) → recompute normals
- Recompute smooth normals (merge + computeVertexNormals)
- Processing overlay for heavy operations

### Textures
- Texture folder picker: scan folder recursively, match by convention (`{name}_diffuse.png`) + fuzzy name matching (case-insensitive)

### Material Inspector
- Draggable floating panel listing all PBR materials
- Live material references (foundation for future material editor)

### Export
- Save As dialog with folder browser, filename pre-filled with original name + extension
- **GLB export (new)**: single self-contained file with geometry, PBR materials, and textures embedded — powered by Three.js GLTFExporter
- Format selector in Save dialog: **Original** (copy source), **OBJ** (geometry only), **GLB** (full scene)
- "Original" option auto-disabled when model has been modified (transforms/simplification/normals)
- Modified models also exportable as OBJ (transforms baked via Three.js OBJExporter)
- File browser auto-refreshes after save
